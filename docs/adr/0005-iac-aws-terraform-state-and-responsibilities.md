# ADR-0005: Хмарний провайдер, зберігання стану Terraform та розподіл відповідальності Terraform / Ansible

- **Статус:** Accepted
- **Дата:** 2026-11-27
- **Контекст проєкту:** BookSwap (Deployment View з лабораторної роботи 1, Docker Compose з лабораторної роботи 2)
- **Пов'язані документи:** ADR-0003 (образи та ізоляція мереж), `infra/terraform/`, `infra/ansible/`

## Context

Для розгортання BookSwap потрібно відмовитися від ручного налаштування серверів (ClickOps) і описати інфраструктуру кодом. Потрібно вирішити:

1. На якому провайдері та в якому обсязі відтворити Deployment View.
2. Де зберігати файл стану `terraform.tfstate`.
3. Що саме робить Terraform, а що — Ansible.

Обмеження: навчальний проєкт, бюджет — безкоштовний ліміт, команда з однієї–двох людей.

## Розглянуті варіанти провайдера

| Варіант | Переваги | Недоліки |
| --- | --- | --- |
| **AWS Free Tier (EC2 t3.micro, eu-north-1)** | Збігається з цільовою платформою з Лаб. 1 (VPC, security groups, пізніше RDS/S3); поняття переносяться на production | 12 місяців Free Tier; потрібна обережність із платними ресурсами |
| DigitalOcean | Простий, передбачувана ціна | Немає безкоштовного рівня; не збігається з Deployment View |
| Локальний гіпервізор (VirtualBox/Libvirt) | Безкоштовно, без ризику рахунків | Немає VPC/Security Group; слабка відповідність діаграмі розгортання |

## Розглянуті варіанти зберігання стану

| Варіант | Переваги | Недоліки |
| --- | --- | --- |
| Локальний `terraform.tfstate` | Нуль налаштувань | Немає блокувань і спільного доступу; чутливі дані на диску |
| **S3 + DynamoDB lock (remote backend)** | Спільний доступ, блокування, шифрування, версіонування | Потребує початкового bootstrap-бакета |
| GitLab-managed state | Вбудоване блокування | Прив'язка до GitLab (репозиторій на GitHub) |

## Decision

### Провайдер

**AWS, регіон eu-north-1.** Для лабораторної створюється спрощений зріз Deployment View: одна VPC, одна публічна підмережа, Internet Gateway, security group, одна EC2 `t3.micro` (Ubuntu 24.04, зашифрований gp3-диск, IMDSv2) та Elastic IP. Керовані сервіси (RDS Multi-AZ, ElastiCache, EKS, CloudFront) — поза обсягом цієї роботи: усі сервіси BookSwap запускаються в Docker Compose на одній VM (як у Лаб. 2). Повна схема — предмет майбутніх ітерацій (спринт 1, «IaC-базис»).

### Мережева безпека (принцип найменших привілеїв)

- Вхідні: `22/tcp` лише з `allowed_ssh_cidrs` (змінна без значення за замовчуванням, `0.0.0.0/0` заборонено валідацією), `80/tcp` та `443/tcp` — відовсюди.
- Порти PostgreSQL, Redis, MinIO та Backend API **не відкриваються**; вони й так живуть у `internal`-мережі Docker (ADR-0003). Захист двошаровий: Security Group + UFW на самому сервері.

### Зберігання стану

- **Для навчальної роботи:** локальний state; `*.tfstate*` та `*.tfvars` внесено до `.gitignore`, у Git потрапляє лише `.terraform.lock.hcl`.
- **Для командної роботи / production:** remote backend S3 з версіонуванням, шифруванням і блокуванням у DynamoDB. Конфігурацію backend підготовлено в `providers.tf` (закоментовано). Перехід — `terraform init -migrate-state`.
- Причина відкладення: bootstrap-бакет сам потребує окремого керування (проблема «курки та яйця»), що надмірно для одного розробника.

### Розподіл відповідальності

| Шар | Інструмент | Відповідає за |
| --- | --- | --- |
| Інфраструктура | **Terraform** | VPC, підмережа, маршрути, Security Group, SSH key pair, EC2, Elastic IP; видає IP як output і генерує Ansible-інвентар |
| ОС і середовище виконання | **Ansible** | Оновлення пакетів, UFW, fail2ban, hardening SSH, Docker Engine + Compose plugin, група `docker`, директорії `/opt/bookswap` |
| Застосунок | Docker Compose (Лаб. 2) / CI/CD (Лаб. 3) | Запуск контейнерів BookSwap |

Межа: Terraform не заходить усередину ОС (без `remote-exec`/`user_data`-скриптів конфігурації), Ansible не створює хмарні ресурси. Єдиний зв'язок — файл `inventory.ini`, який генерує Terraform.

## Consequences

**Позитивні:**

- Інфраструктура відтворюється командами `terraform apply` + `ansible-playbook`; зміни проходять через Git та PR.
- Відповідність Лаб. 1: мережевий периметр і сегментація описані кодом.
- Ідемпотентність: повторний запуск плейбука дає `changed=0`.

**Негативні / компроміси:**

- Одна VM — єдина точка відмови; NFR-03 (99,5 %, Multi-AZ) для цього етапу не виконується.
- Локальний state не підходить для команди: втрата файлу означає втрату зв'язку з ресурсами.
- Дані та БД на тій самій VM, що й застосунок (відмінність від RDS у production-схемі).
- Elastic IP і VM поза Free Tier тарифікуються; після демонстрації виконати `terraform destroy`.
- Tfstate містить чутливі значення — доступ до нього має бути обмежений.
